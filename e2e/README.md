# Portable synthetic browser smoke

Run `npm ci`, `npx playwright install chromium`, then `npm run test:e2e` from the repository root. The exact test dependency is `@playwright/test@1.64.1`; its bundled Chromium is revision 1248 (Chrome for Testing 156.0.8078.4). The test server uses `127.0.0.1:4173` and Playwright creates a fresh, disposable browser context for each test. Never point these tests at a user browser profile or `localhost:5173`.

The core check loads the S01 app shell, writes a three-slot synthetic scene through the app's storage API, reloads the page, then checks visible narrative output, clipboard copy, save, and a small legacy full-library ZIP export/validate/restore roundtrip. The fixture contains text only. The additional checks cover duplicate-save confirmation and storyboard order plus collection return. `sceneDuplicates.ts` and `storage/projects.ts` are file capability gates because the earlier stacked branches do not contain those features. A missing capability produces an explicit Playwright skip and count; an assertion failure never becomes a skip.

CI records the exact checkout SHA, Node version, Playwright version, Chromium revision, unit-test totals, browser test names and outcomes, and workflow URL in `qa-results/summary.json`. It uploads only that public synthetic summary, capped at 64 KiB, for seven days. Raw JUnit and Playwright JSON reports stay in ignored `qa-results/`; no screenshots, traces, video, browser profiles, or media are uploaded. Large ZIP64 stress work is a separate manual local workflow with disposable data and is intentionally outside this hosted PR suite.
