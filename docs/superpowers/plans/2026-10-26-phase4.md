# Phase 4 implementation plan

> Use superpowers:subagent-driven-development for independent modules and final review; preserve the user brief and the linked design as authority.

**Goal:** Advisory preflight, lean/provider exports, approved identity anchors and explicit reference packs without rewriting canonical history.
**Architecture:** Pure read-only modules first; optional versioned record fields and user-confirmed actions second. Project JSON and stored outputs remain unchanged. Two stacked PRs, no merges.
**Tech stack:** Existing React/TypeScript/Vite/IndexedDB/fflate/Vitest; isolated Chromium Playwright. No new application dependencies.
**Spec:** ../specs/2026-10-26-phase4-design.md and the complete user Phase 4 brief.

## Global constraints and review focus

- No user data/profile/storage resets, AI/backend calls, automatic prompt correction, automatic anchor approval or automatic reference filtering.
- Required scene/confirmed variant errors remain blocking; subjective preflight never prevents export.
- Negated camera motion/front-quarter/voiceover must not yield confident false conflicts.
- Existing Project JSON and historical three-mode outputs stay byte-identical.
- Anchor approval links to master identity revision, with stale/concurrent edits handled and historical choices frozen.
- Pack identity is association-based, and duplicate roles retain their records while binaries are deduplicated.
- Missing selected media remains visible and cannot silently produce an incomplete ZIP.
- Optional restore fields must validate before writes; synchronous failure must abort the whole transaction.
