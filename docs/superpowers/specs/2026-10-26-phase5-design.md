## Architecture decisions

Use optional metadata in the existing eight version-1 stores. A ninth ProjectShot store would require a migration and a second membership transaction surface; embedding a versioned project in Collection makes per-project operations atomic without a schema upgrade. Keep repository commands small and transaction-based. Avoid writing whole stale Collection objects from UI; read current records and apply operations in one IndexedDB readwrite transaction. Concurrent tabs must preserve independent membership/status/reorder operations or reject an expected-revision conflict clearly.

Canonical source prompts, saved snapshots, Full/Structured/Compact outputs and Project JSON are not regenerated by project changes. New lineage/media metadata is ignored by canonical serializers. The full-library ZIP stays schema 1 and includes all records/media; optional-field validators run before replacement. Keep the tested synchronous/asynchronous rollback protection. No dependency additions, AI backend, paid integrations or external generation.

## Stage A — workflow reliability

### Duplicate saves

New pure `sceneDuplicates.ts` compares deterministic meaningful candidate data: component snapshot/source IDs and effective prompt/override values, dialogue, instructions, settings, negative text, actual canonical output strings after manual overrides, generation choice and explicit reference pack. Ignore only presentation/title, record IDs/timestamps, input revision alone, result/review metadata. Sort object keys, preserve array order and exact authored strings. Same title/character alone never implies duplicate; changed camera/dialogue must not match. Construct the pending saved representation using existing assembly before comparison so saved combined negatives match correctly.

`saveSceneFromDraft(draftId, options?)` keeps its existing return type. Optional options include `{ duplicateDecision?:'version'|'take'; duplicateOfSceneId?:string; requestId?:string }`. With no decision and meaningful duplicate, throw exported `SimilarSceneError` with matching existing scenes; do not write. With an explicit decision validate the chosen existing scene and create a distinct ID. Record optional sourceDraftId/sourceDraftInputRevision and versionOfSceneId/separateTakeOfSceneId/requestId. Repeated requestId returns the same result, scoped to the same draft. Duplicate checks and inserts happen inside one transaction over draft/scenes/assets/media, covering separate tabs. A synchronous UI ref plus busy state prevents rapid concurrent clicks, including modal saves. Never delete a duplicate or overwrite its prompt.

Output duplicate dialog: exact message “A similar saved scene already exists.”, choose relevant existing scene if several, Open Existing Scene / Save as New Version / Save as Separate Take / Cancel. Every path preserves unfinished input and historical outputs. Error states are visible, busy is disabled. Repository and UI rapid-double-click tests are required.

### Media naming

Add optional `MediaAsset.displayName`, `MediaAsset.exportFilename`. Original `filename`, safeFilename, MIME, IDs and binary/provenance never change. Optional MediaLink/ReferencePackEntry snapshot displayName/exportFilename preserve names chosen for future saved associations; legacy associations continue using original metadata. `mediaNaming.ts` supplies `getMediaDisplayName`, safe export-name validation and `captureMediaNames(links,mediaMap)`; do not change altText to rename a file. Display names have a bounded nonblank length; export basenames reject path separators, dot traversal, control characters and reserved names, and require a real extension compatible with actual MIME (jpeg/jpg, png, webp, svg for legacy, mp4/webm). Empty optional export name restores original naming. Archives resolve collisions deterministically without overwriting.

New `storage/mediaMetadata.ts` exports `updateMediaNames({mediaId,displayName?,exportFilename?})`, reading/writing only media metadata transactionally, and returns MediaAsset. Existing prompt editor exposes Original Filename read-only, Display Name, Export Filename and Accessibility Description separately. New `MediaMetadataEditor` reusable with save/errors. ReferenceBoard/pack/gallery selectors display name fallbacks consistently. Individual original bytes remain identical; selected downloads use validated export names when explicitly captured. Historical saved references/pack exports do not read later live name changes into their frozen metadata. Repository freezes current optional names for newly saved links/snapshots/reference packs without changing original filename fields. Backup validates new optional fields and accepts legacy lack of fields.

### Collection UX

Expose `coverMediaId` in create/updateCollection, with `null` explicitly removing it and undefined preserving. Reuse existing image MediaAsset; uploaded cover uses existing validation/saveMediaAsset, no deletes. Shared accessible CollectionCoverPicker supports existing character/scene reference/result images and separate upload. Fallback cover is computed from member scenes (result then reference), never written silently. Cards show cover, title/description, scene count, known intended runtime + unknown count and updated date.

`collectionNavigation.ts` creates/validates context route `#/output/:sceneId?collection=:id&tab=:tab&view=:grid|list&sort=:sort&filter=:filter&shot=:shotId`. IDs must resolve against current snapshot, scene must belong to that collection; invalid/missing origins use Saved Scenes. Back route carries validated state. A per-session scroll map keyed by the full collection route restores scrolling; never rely exclusively on history.back. Direct outputs retain Back to Saved Scenes. App parses and passes context without changing existing routes.

Saved Scene cards show a CollectionMembershipBadge with “Not in a Collection”, “In [name]”, “In N Collections”; accessible popup/dialog lists current collections and links. Membership modal defaults to searchable checked list and Done; full creation form behind + New Collection disclosure. Membership updates affect only target entity, never duplicate a SavedScene.

## Stage B — ordered projects and takes

Add optional `Collection.project: {version:1,revision:number,shots:ProjectShot[]}`. Additional Stage C fields remain optional. Shot: `{id,order,code,title,takeSceneIds:string[],selectedSceneId?,status,plannedDurationSeconds?,takeNotes?:Record<string,string>,continuityNotes?,intentionalWardrobeChange?,firstFrameMediaId?,lastFrameMediaId?}`. Status enum planned/prompt_ready/generated/reviewed/final, explicitly user-set. `takeSceneIds` distinct; preferred take must be in the list and resolve to an existing scene on mutation/restore. Do not mutate a SavedScene to change status/title/sequence/notes. Store explicit display code (03A) independently of numeric sequence.

**Single source of truth:** once project exists, shots/takes are authoritative for scene membership; Collection.members scene refs are a derived, deduplicated compatibility projection of all takeSceneIds. Preserve non-scene members and existing addedAt values. Removing a scene through the membership modal removes that take from every shot; empty shots become planned placeholders, selection falls back to an existing remaining take when explicitly removed. Adding a scene through membership appends one shot if not already used. Removing a shot removes membership only when no other shot references that scene. Deleting a saved scene via the existing confirmed action removes its take references and recalculates memberships. Each operation is atomic and project-scoped.

Legacy projects initialize lazily from existing scene-member order using deterministic IDs `collectionId:legacy:sceneId`, codes 01/02..., status prompt_ready for existing linked scenes. Missing referenced scenes display a visible missing state; mutating/restore operations reject invalid newly selected takes. Do not parse titles as order or migrate all collections eagerly.

`projectStoryboard.ts` provides pure `getProjectShots(collection, scenes)`, `projectMembersFromShots`, `getProjectRuntime` (known total + unknown count, no guessed 8 seconds), and selected-scene helpers. `storage/projects.ts` commands read latest Collection inside a transaction: initializeProject, addProjectShot(beforeId?/afterId?/sceneId?), updateProjectShot(id,patch), reorderProjectShots(orderedIds,expectedRevision?), removeProjectShot, addProjectTake, removeProjectTake, selectProjectTake. Validate IDs, unique order, allowed fields, finite durations and selected take. Prefer operations over stale entire-record saves. Drag-drop and Move Up/Down operate on full ordered ID list and reject stale sequence revisions; retain all metadata. Planned duration overrides are separate from immutable scene settings; actual usable video metadata shown separately.

Collection detail becomes `CollectionWorkspace` with Storyboard (default with scenes), Characters, Assets, Results, Project Details. Thumbnail-first grid/list, shot code/title, selected character/take, intended duration/unknown, status/review/dialogue badge and compact actions. Search/status filter/counts/progress. Add Existing Scene, Add Planned Shot, Insert Before/After, explicit remove confirmation, save order, status/duration/code editing. Details retains edit/cover/delete collection and exports. Legacy non-scene assets/variants remain accessible. No giant prompt paragraphs by default.

Takes: add existing distinct scene, preferred selection, notes, remove association only. Compare dialog side-by-side exact camera/action/dialogue/settings/review/provenance/result, no scores. New Take copies the selected saved scene to Builder carrying validated project+shot route context through Assemble and Output. Extend save options with projectTarget and attach new saved scene to the shot in the same repository transaction; invalid target aborts save. Existing duplicate dialog remains explicit for unchanged compositions. A new take never overwrites a scene.

## Stage C — continuity and scripts

Optional `Collection.project.cast: CharacterBibleEntry[]`, each keyed by characterId, with optional manually entered name/storyRole/voiceNotes/personality/distinctiveFeatures/accessories/relationships/notes/approvedWardrobeVariantIds/referenceMediaIds. Existing identity/anchor is displayed read-only with links/status; edits never write the master. Project cast can be explicitly linked or derived read-only from selected shots; no automatically inferred traits. Validate reference asset/variant types, no orphan selected IDs on mutation.

`projectContinuity.ts` computes ordered dialogue records using selected takes and exact canonical strings, and adjacent same-character wardrobe changes using source IDs/effective descriptions. Missing wardrobe is unknown, not a conflict. Per-shot intentional reason enum new_day/costume_change/flashback/timeline/deliberate/other with notes makes advisory changes reviewable, never auto-replaces an outfit. Display tracker and exact Script board under Characters, with copy-line and UTF-8 script document export; no SRT/time inference.

First/last-frame references are explicit existing image IDs or new validated image uploads on ProjectShot. Adjacent frame comparison enlarges originals; no extraction or image/video generation. Show missing files rather than hiding associations. Never add new media cleanup. Preserve new references through backup/restore.

Transitions are optional `Collection.project.transitions: {id,fromShotId,toShotId,type,durationSeconds?,description,notes}[]`, with enum straight_cut/match_cut/dissolve/j_cut/l_cut/bridge_shot/custom. Store stable edge IDs, not a mutable next-index. Reordering keeps metadata on its original pair and flags nonadjacent transitions for review; never silently retarget notes. Removing a shot explicitly removes incident transition metadata as part of confirmed project removal. Editor between adjacent cards plus detached-transition review list. All project-only metadata.

## Stage D — productivity and bounded export

Select multiple shots for status, stable group move up/down, add their selected scenes to another collection, prompt export and confirmed remove-from-project. Library multi-scene selection supports add to collection and exact prompt export; production assignment is scoped to a chosen project, never global. No permanent bulk deletion.

`projectExport.ts` constructs `krakinai.project-export.v1`: ordered shots, selected/take references, snapshot-derived exact structured prompts and Project JSON, optional Generation JSON resolved with saved=true, script, continuity/status/frame/transition metadata, cover and reference manifest with original filename/MIME/ID and frozen association purpose/role/export name. Explicit reference packs control per-scene selected files; absent pack uses authoritative legacy checklist. Deduplicate binary bytes by media ID across role associations without losing manifest entries; safe unique filenames/shot directories use ordinal and stable IDs, not bare titles.

No selected reference may disappear silently: validate all required media before archive creation and return exact missing associations. Optional incomplete shots/missing saved takes appear in manifest warnings and storyboard; user can export planned projects with warnings, but missing selected binary export is blocked unless user explicitly excludes that association through pack/selection UI. Cover/frames are included when selected. Project ZIP is clearly not a full backup and has no restore-library action.

Bound this MVP to 128 MiB selected distinct uncompressed media + 16 MiB generated text/manifest, max 2000 archive entries, with a conservative preflight upper bound before reading blobs. These are project-export bounds only; never change user's library/backup constants. Use fflate async zip in worker and async reads, progress/busy state and cancellation or clear bounded completion; on UI thread avoid sync compression for large packs. Test limit rejection without allocating giant fixtures; memory/size evidence must not imply safety at 5 GiB library limits. UI warns exact bound before export and provides actionable errors. ZIP SHA-256 tests cover originals, duplicate names, traversal names, repeated roles, Unicode dialogue and ordering; never claim production readiness or full-library size suitability from a small fixture.

## Builder-review rulings (binding implementation details)

1. All asset/variant/scene deletion paths must read affected collections in the write transaction, rather than overwrite stale pre-read snapshots. Stage B makes these use the shared project membership projection. Preserve historical unavailable cast/wardrobe metadata visibly; new selections/restore must reject invalid live references deliberately.
2. Project member projection is the first-occurrence union of take IDs in ordered shots; retained addedAt and non-scene refs survive. Restore rejects inconsistent project/member sets, duplicate IDs/orders and noncontiguous orders; runtime reads tolerate damaged legacy links visibly, while new links/preferred choices and restores remain strict. updateProjectShot cannot arbitrarily replace order/take arrays/selected take.
3. Save request tokens bind to draft input revision, meaningful candidate, explicit decision/duplicate target and projectTarget. Reject token reuse after edited inputs/changed decision/target. Retain one token for retries of the same operation; modal decision is a new bound operation token. Validate an explicit duplicate target is a current meaningful match. Test rapid explicit decision clicks too.
4. Optional name snapshots also cover newly added saved result links; retained historical links and legacy links never fall back to live optional names. Add optional displayName/exportFilename/namesCaptured to MediaLink/ReferencePackEntry. captureMediaNames freezes names once, including explicit no-override, and never rewrites already captured links. One binary with several frozen requested names uses its first ordered association for the archive path and retains every requested name in manifest metadata.
5. Backup explicit MediaAsset serialization and reconstruction must both include the optional names. Validate nested links in variants/templates/drafts/scenes/references/results/packs, not assets alone. Extend referenced-media collection for explicit packs and later cast/frame references; no automatic cleanup. Preserve Phase 4's acceptance of historical optional pack metadata with missing blobs: the ownership collector includes optional IDs by default, while strict restore canonical-integrity checking passes includeOptionalMetadata:false. New selections must resolve, and project/reference ZIP exports must block missing selected binaries. Do not change an existing accepted-backup regression to reject it.
6. Duplicate comparison excludes presentation titles/sourceTitle/display/export names and lineage/request metadata, but includes source IDs/revisions, media association ID/role/order/purpose and actual canonical outputs/manual text. Renaming media must not bypass duplicate protection.
7. Transitions have unique IDs, no self-edges, existing endpoints and at most one directed edge per pair. Durations do not alter planned runtime. Stable detached edges remain visible after reorder; explicit removal clears incident edges atomically.
8. Export checks conservative UTF-8/JSON escaping bounds before giant text allocation, checks actual blob sizes and entry counts, reads with bounded concurrency, and verifies large-path worker compression/responsiveness. No project zipSync fallback. Document peak copies and bounds honestly.
9. Every meaningful project mutation increments revision; stale full-list reorder rejects with a visible conflict. Narrow status/notes operations merge against latest state. Test actual independent DB connections/tabs. Refresh library snapshot on focus or broadcast so committed changes become visible.
10. Validate shot context against its project and output scene, with bounded enums/encoded route values. Unknown/deleted context safely falls back. Safe export basenames also reject Windows reserved names, trailing dots/spaces and case-insensitive collisions.
