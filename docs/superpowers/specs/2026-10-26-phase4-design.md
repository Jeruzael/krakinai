## Stage A — Read-only exports and preflight

### Preflight contract

`src/domain/scenePreflight.ts` exports `runScenePreflight(source: SceneDocumentSource & { extraRequiredSlots?: BuilderSlot[] }, availableMediaIds?: ReadonlySet<string>): PreflightFinding[]`.

`PreflightFinding` contains `id` (stable rule+evidence identity), `ruleId` (P000 or P001–P008), `severity` (`blocking`|`review`|`information`), `title`, `components: (BuilderSlot|'dialogue'|'settings'|'instructions'|'references')[]`, `evidence: {component, text}[]` (exact source excerpts), `explanation`, and `suggestedActions: string[]`. P000 covers current assembler-required ingredients/validation; P006 is confirmed parent mismatch. Advisory P001 direct gaze+explicit rear placement; P002 explicit locked/static camera+physical camera movement; P003 explicit morning/day vs evening/night; P004 photorealistic vs fully stylized cartoon/3D informational; P005 speaker/name mismatch, except intentional narrator/voiceover/off-screen; P007 on-camera visible speech vs rear/extreme composition; P008 unresolved selected IDs. Handle negation and front three-quarter explicitly; do not match the unmodified master's quoted examples or derive numeric confidence. Voiceover/off-screen alone do not imply lens interaction. Deduplicate findings; never change inputs. An empty optional component does not create a finding.

`ScenePreflightDialog` takes findings, onClose, onViewSource(component), onEditComponent(component), readOnly?, and optional current local intentional IDs. Intentional acknowledgement is local advisory state in Stage A, keyed to evidence so changed wording does not inherit an old acknowledgement. Blocking findings cannot be marked intentional. Saved scene edits use Edit a Copy. Sources are shown directly in the dialog; current library revisions must not replace the preserved evidence. Builder opens existing component drawers for editing; dialogue/instruction sections can be focused directly. Output also offers Preflight without blocking copy/export for advisory findings.

### Generation document and providers

`src/domain/generationDocument.ts` exports `GenerationExportOptions`, `GenerationReference`, `buildGenerationDocument(source: SceneDocumentSource, options?: GenerationExportOptions)`, and `serializeGenerationJson(source, options?): string`.

`GenerationReference` contains associationId?, mediaId, sourceSlot?, purpose?, order, filename, mimeType, role, altText. No blobs, paths or transient URLs. Options provide optional `identity: { source:'master'|'approved_anchor'; description:string }` (approved/resolved by the Stage B domain, not arbitrarily inferred) and optional explicit `references: GenerationReference[]` (an empty array means explicitly none).

Schema `krakinai.generation-prompt.v1`: stable ordered keys `schema`, `scene` (title,type,durationSeconds,aspectRatio,instructions,toolNotes), `character` (null or name from snapshot title, identitySource, description), wardrobe/environment/action/camera/lighting/style (one effective complete string or null), dialogue (canonical mode/speaker/language/deliveryNotes/exactLine/captionPreference), negativeInstructions (array), references. Each identity description appears only once; no compact variants or archival source/snapshot metadata. No guessed camera structure.

Deduplicate negative constraints only in generation output. Normalize whole source field segments for comparison (trim, Unicode normalization, case/whitespace folding) and preserve the first segment's exact original wording and order. Never split comma-containing phrases or rewrite semantics. For old saved combined negative strings, remove only an exact already-known component-joined prefix to avoid including both that prefix and the whole archive string; leave unrecognized combined text intact.

`src/domain/exportPresets.ts` exports `EXPORT_PRESETS`, `type ExportPresetId='generic_structured'|'gemini_omni_flash'|'custom'`, `formatGenerationText(source, presetId, options?): string`, and `getProviderNotices(source, presetId, options?): string[]`. All adapters are reversible views, not writes. Preserve every selected effective component and exact spoken line. Generic uses sections; Omni uses explicit speaker-action plus colon without adding outer quotation marks, retaining user-authored internal quotes. Voiceover/off-screen remain audio direction without visible speech. Negatives appear as ordinary text constraints, not a fabricated provider API parameter. Custom is a generic starting template, not persisted user presets.

Official guidance verified 2026-10-26: ai.google.dev/gemini-api/docs/omni (current model gemini-omni-1.1-flash, reference roles, no native negative prompt parameter, current video reference limitations); ai.google.dev/gemini-api/docs/video (Veo 3.1 Preview retired 2026-10-22); deepmind.google/models/gemini-omni/prompt-guide/ (framing/motion/style/light/location/action); docs.cloud.google.com/gemini-enterprise-agent-platform/models/video/best-practice (speaker/action colon, no decorative quotation wrappers, focused single scene). These are recommendations and scoped documented metadata, not a guaranteed request contract. Unknown limits stay null/unknown; no guessed attachment/duration constraints. Source links and verification date ship in preset docs and metadata. Do not quote large passages.

## Stage B — Optional persistent user choices

### Identity anchors

`PromptAsset.identityRevision?: number` for characters. Legacy fallback is `asset.identityRevision ?? asset.revision`; subsequent saves materialize/preserve it, incrementing only when the master prompt text changes. Asset revision behavior remains otherwise intact. `identityAnchor?: { text:string; approvedText?:string; approvedMasterIdentityRevision?:number; approvedAt?:string }`. A draft edit never grants approval; retain previous approval metadata for comparison/history. Valid approval requires exact text===approvedText, nonblank approved text, matching master identity revision and approval date. Source master edits preserve anchor text and metadata but derive stale status. Never alter the original master string.

Pure `identityAnchors.ts`: current master revision, approval status, and generation identity resolution. Repository operations save a draft anchor separately and explicitly approve against the current master in a transaction, with optional expected revision to reject concurrent master changes. Both leave master prompt text unchanged. UI `IdentityAnchorPanel` on character detail: revision, text editor, Save Draft Anchor, Approve Anchor, last approval metadata, Copy Anchor, Compare with Master. No generated traits or automatic anchor drafting.

Character `ComponentSnapshot` gains optional identityRevision/identityAnchor, copied when a user selects/refreshes the source. Project JSON ignores these additions and remains byte-identical for the same legacy inputs. `SceneDraft`/`SavedScene` gain optional `generation: {identitySource:'master'|'approved_anchor'; anchor?:{text,approvedMasterIdentityRevision,approvedAt}; fallbackReason?:string}`. Selecting an anchor explicitly validates both selected master snapshot and current source identity revision, then captures approval metadata. Draft export checks live identity revision only to reject stale approval; it still falls back to the selected snapshot's master text, never a newer library prompt. Saving a scene freezes the effective generation choice after checking current approval; saved generation exports use only captured metadata and do not change when live assets change. Legacy scenes default to master. Edit a Copy preserves captured choices and requires explicit refresh/reapproval when stale.

### Reference packs

Optional `ReferencePack` on drafts/scenes: `{version:1, entries: ReferencePackEntry[]}`; absent means unchanged legacy behavior, present with no entries means explicitly none. Entry fields: associationId, mediaId, sourceSlot (BuilderSlot|'result'|'legacy'), sourceId, sourceTitle, role, altText, filename?, mimeType?, purpose ('identity'|'outfit'|'environment'|'motion'|'general'), order. Association IDs encode origin/source ID/media ID/role/view-label/alt text plus occurrence only for otherwise identical duplicates; not solely an array position. Stable across unrelated reordering, title edits, source revisions. Selected entries retain their metadata even if their association or blob becomes unavailable.

`referencePack.ts` gathers snapshot links, unmatched saved checklist records and external result links, differentiating component origins, references/samples/results, images/videos, demo illustrations and missing blobs. UI opens with no preselected proposal for a new pack; Apply Suggested Pack is an explicit intermediate user action (identity/outfit/optional environment only, excluding demo/results), and Apply Reference Pack is a separate explicit final confirmation. Deselecting changes only pack selection. Reordering and purpose changes are local until Apply. Saved manager is read-only; Edit a Copy is required to change historical selection.

ZIP generation is separate from full backup: versioned manifest contains every selected association in order, binary paths contain each selected media ID once. Preserve original binary bytes, use safe unique basenames, include role/origin/purpose labels. Missing selected blobs block ZIP export with a precise message; keep their entries visible so users can explicitly adjust selection. Individual original downloads and matching checklist copy remain available. No automatic filtering of legacy exports.

### Persistence and restore

Keep IndexedDB version 1 and eight stores. Add optional fields only; no mass rewriting/backfill. Save/draft/scene-copy/immutable scene creation must clone/preserve them. Backup serializes them as part of existing records. Restore validates their shape, bounds, enum values, unique association IDs/media metadata/order and approval metadata before any write while accepting old records without these fields. Missing IDs in optional pack metadata can remain represented as missing; existing canonical media integrity rules stay intact. Transactional replacement must explicitly abort synchronous write failures as well as asynchronous failures. Add a real rollback regression, not only malformed JSON rejection.
